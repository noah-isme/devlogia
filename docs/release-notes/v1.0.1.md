# Devlogia v1.0.1 (dev)

## Release Scope

v1.0.1 is scoped as a **CMS/blog release**. The release target is a stable publishing product: admin authentication, RBAC, post/page CRUD, media upload, public `/blog`, search/pagination, RSS, sitemap, OG images, and visual E2E coverage.

AI recommendations, tenant workspaces, marketplace billing, plugins/extensions, federation, and developer ecosystem workflows remain beta/foundation areas. They are not release commitments for v1.0.1.

## Highlights

- Developer experience improvements for local E2E workflows.
- Faster, more reliable E2E pipeline with MySQL readiness checks and pnpm caching.
- Production health endpoint and deployment templates for Vercel.
- Visual smoke screenshots for login, admin dashboard, public blog, and the new-post editor.

## Changes

### Local Tooling

- Added `pnpm dev:seed` helper to bootstrap the database quickly.
- Added MySQL availability checks before running `pnpm test:e2e:full`.
- `pnpm test:e2e:full` prepares the test database from `DATABASE_URL`, applies migrations, seeds deterministic fixtures, and runs Playwright.
- Introduced reusable `scripts/check-db.js` for connection diagnostics.

### CI/CD

- Added database readiness checks before running migrations.
- Cached the pnpm store to shorten install times on re-runs.
- Ensured Prisma can build without a live database by injecting a `fake://stub` fallback URL.

### Runtime & Deployment

- Added `/api/health` endpoint returning `{ status: "ok", version: "1.0.1" }`.
- Added `.env.production.example` template with AI/webhook/DB configuration.
- Added `vercel.json` with deterministic install/build commands for Next.js 16 deployments.

### E2E and Visual QA

- Fixed the admin login route so it renders outside the admin console shell.
- Fixed CSP handling so Next/React hydration works in local E2E runs.
- Updated public blog tests and links to use `/blog` as the article index.
- Added Playwright screenshot/trace/HTML-report retention.
- Added visual smoke screenshots stored in `test-results/visual-smoke-*`.

## Beta Feature Strategy

Do not enable every beta feature at once. Promote beta areas in this order:

1. AI assist editor, because it is closest to the CMS/blog workflow.
2. Lightweight recommendations and personalization.
3. Tenant and workspace support.
4. Marketplace and billing.
5. Federation and developer ecosystem workflows.

## Current Blockers

- Full E2E still logs transient Next dev-server `Error: aborted` noise during parallel browser navigation, but the suite passes.
- `pnpm build` still emits non-blocking warnings for stale `baseline-browser-mapping`, static-build database skips, Prisma `$use` middleware availability, and edge-runtime static generation.
